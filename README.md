# Penetration Testing Engagement Assessment

## Executive Summary

Security assessment project focused on evaluating a penetration testing engagement plan for a fictional healthcare organization preparing to deploy an upgraded electronic medical records system.

Reviewed the proposed penetration testing approach to identify gaps in testing scope, authorization, Rules of Engagement (RoE), operational risk management, sensitive data protection, and vulnerability reporting.

Developed recommendations aligned with NIST SP 800-115, the HIPAA Security Rule, and established penetration testing best practices to strengthen engagement planning, protect sensitive healthcare information, and reduce the risk of operational disruption.

## Project Overview

Evaluated a scenario-based penetration testing engagement plan covering internal network testing, external network testing, and phone-based social engineering.

The healthcare environment relied on electronic medical records, patient payment systems, Active Directory, endpoint antivirus, and network infrastructure supporting daily clinical operations.

The assessment examined whether the proposed testing activities aligned with organizational security objectives, healthcare data protection requirements, and operational continuity needs.

Identified weaknesses in engagement planning and proposed improvements to support a more controlled, authorized, and risk-based penetration testing process.

## Key Security Findings

The scenario-based engagement plan assessment identified several security planning weaknesses:

- Testing scope did not clearly identify all authorized and excluded systems
- Formal Rules of Engagement were not sufficiently documented
- Written testing limitations and restrictions were not clearly defined
- Communication and emergency escalation procedures were incomplete
- Procedures for protecting sensitive patient information during testing were missing
- Vulnerability reporting and risk prioritization requirements were insufficiently defined
- Testing activities were not clearly coordinated with critical healthcare operations
- Contingency and recovery procedures were not established
- Some proposed tool descriptions and testing assumptions were technically inaccurate
- Engagement planning did not fully align with recognized security testing guidance

## Recommendations & Proposed Improvements

### Rules of Engagement

- Define authorized systems, testing boundaries, and prohibited activities
- Establish clear engagement responsibilities and communication requirements
- Document emergency contacts and escalation procedures
- Define conditions requiring testing to be suspended or stopped
- Coordinate testing activities with organizational stakeholders

### Scope & Authorization

- Identify all in-scope and out-of-scope systems
- Obtain documented authorization before testing activities
- Establish testing limitations and approved techniques
- Define procedures for managing changes to engagement scope
- Coordinate testing windows to minimize operational disruption

### Vulnerability Reporting & Risk Management

- Establish a consistent process for documenting security findings
- Define vulnerability severity and prioritization criteria
- Include actionable remediation recommendations
- Establish reporting expectations and stakeholder responsibilities
- Prioritize weaknesses based on security impact and operational risk

### Sensitive Data Protection

- Define procedures for handling protected health information
- Limit access to sensitive information during authorized testing
- Establish secure storage and disposal requirements for collected data
- Document confidentiality and data protection responsibilities
- Align engagement procedures with healthcare security requirements

### Contingency & Recovery Planning

- Establish response procedures for unexpected system instability
- Define emergency notification and escalation requirements
- Document testing suspension and recovery procedures
- Coordinate recovery responsibilities with IT and security personnel
- Protect the availability of critical healthcare systems during testing
